# 恢复与交接协议

计划目录是跨会话、跨 agent 恢复的持久事实源。本文件定义中断后如何无损恢复、如何交接、以及如何做最终验收。实施 agent 在每个会话开始时，以及任何中断、压缩、交接之前使用本协议。

## 1. 需要恢复的典型场景

- 上下文被截断或执行 `/compact` 后，对话记忆被压缩或丢失。
- 会话被中断、超时、进程被杀死。
- 新会话、新 agent 接手（没有原对话历史）。
- 并行子任务完成后，需要把结果合并回主流程。

## 2. 恢复启动流程（三分钟回到现场）

1. 读 `AGENTS.md` → 确认导航、执行规范与维护规则。
2. 读 `progress.md` → 确认阶段状态表、当前 in_progress 阶段、Todo、阻断、最近验证记录。
3. 只读当前阶段文档 → 确认门禁与未完成 Todo，从最后落盘的位置继续。

若 `progress.md` 的「下一步」为空或与实际状态不符，以最近验证记录和实施偏差推断真实状态，并把推断过程记入实施偏差，而不是凭空重启整个计划。

## 3. 交接清单（Handoff Checklist）

任何需要他人或他会话接手的时刻，在 `progress.md` 中确认以下各项齐备：

- 当前阶段与状态（pending / in_progress / blocked / completed）。
- 本阶段已完成的可验证单元、对应证据位置。
- 尚未完成的 Todo，以及下一步**第一条可执行动作**。
- 未决问题、阻塞与恢复条件。
- 最近一次验证或提交记录。

缺少任何一项，先补写再交接；禁止把「对话里讲过」当作已交接。

## 4. 上下文压缩 / 会话结束前的落盘模板

在 compact 或退出前，把以下内容写入 `progress.md`：

```markdown
## 当前断点（YYYY-MM-DD HH:MM）

- 阶段：NN-xxx（in_progress）
- 已完成：<可验证单元 + 证据位置>
- 未完成：<Todo 列表>
- 下一步：<第一条可执行动作>
- 未决：<问题或阻塞>
```

恢复时读取该断点，直接从「下一步」继续。

## 5. 并行子任务的边界与输出契约

- 每个子任务必须写明：目标、输出格式、允许使用的工具/来源、边界（明确哪些不做）。
- 子任务产物落盘（文件或 `progress.md` 的引用），主 agent 只接收摘要与引用，不在对话里搬运大段内容。
- 子任务之间不允许依赖未声明的中间状态；需要共享的契约（接口、数据格式）先写入阶段文档。
- 子任务完成后，其结论与证据合并进 `progress.md`，并标注来源。

## 6. 最终验收（对照最初方案）

整个计划完成时，不允许只凭「最近好像都做完了」收尾：

1. 重读 `progress.md` 的「目标」与「完成条件」，以及 `AGENTS.md` 中记录的原始边界。
2. 逐条核对所有阶段的完成门禁证据与「输出契约」交付物。
3. 检查「实施偏差」：确认每一项偏离都有记录，且没有偏离最初范围与非目标。
4. 执行最终验收：全量测试、发布或切换、回滚演练、旧机制清理、文档同步，逐项留下证据。
5. 在 `progress.md` 写入「最终验收」结论：哪些条件满足、哪些遗留、遗留的处理方式。

任何遗留项都必须显式记录并给出处理方式，禁止通过不写来「显得完成」。
