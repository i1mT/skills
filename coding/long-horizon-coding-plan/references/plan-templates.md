# 计划文档模板

只在创建文档时读取本文件。根据仓库实际情况删减不相关章节，但不要删除跨会话恢复和完成判定所必需的内容。

## 导航入口：AGENTS.md

```markdown
# <计划名称>

本目录长期追踪 <目标和边界的一句话说明>。

- [`progress.md`](progress.md)：长期状态、Todo、决策、风险、阻断、验证证据和实施偏差的唯一事实源。
- [`01-....md`](01-....md)：<阶段目标>。
- [`02-....md`](02-....md)：<阶段目标>。

## 计划执行规范

1. 除第一个阶段外，所有阶段进入之前要确认上一阶段的单元测试通过。若不通过，将上一阶段状态改为 in_progress，继续完善。
2. 开发实现该阶段目标
3. 跑单元测试
4. 创建sub agent，让它审核本阶段完成的内容，确认能不能进入下一个阶段。若子智能体发现有 P0 问题 或者 实现与规划不符，则打回进行修改。
5. 子智能体审核通过，进入下一个阶段。

## 维护规则

- 开始、完成或阻断任何阶段时，先更新 `progress.md`。
- 阶段文档维护方案和完成门禁；动态状态只写入 `progress.md`。
- 实施产生的架构决策、验证证据和偏差必须能够由后续 Agent 找到。
- <本计划特有的不变量和禁止事项>。
```

## 长期事实源：progress.md

```markdown
# <计划名称>进度

状态：`pending`

创建日期：YYYY-MM-DD

最后更新：YYYY-MM-DD

## 目标

<最终目标、用户价值和主要技术路径。>

## 完成条件

- <可由真实行为或证据判断的最终条件>。
- <兼容、安全、数据和回滚条件>。
- <测试、文档和发布条件>。

## 当前基线

- `<真实标识符或路径>` 当前负责 <行为>。
- <现有测试、数据模型、限制和可复用能力>。

## 阶段进度

| 阶段 | 状态 | 进入条件 | 完成门禁摘要 |
|---|---|---|---|
| 01 ... | pending | 计划批准 | ... |
| 02 ... | pending | 阶段 01 完成 | ... |

## Todo

### 计划与基线

- [x] 创建长期计划并完成当前实现调查。
- [ ] 完成阶段 01。

### 实施

- [ ] 完成阶段 02。
- [ ] 完成阶段 03。

### 文档与交付

- [ ] 同步更新相关事实文档。
- [ ] 完成发布、回滚和交接证据。

## 核心决策

- YYYY-MM-DD：<决策>；原因：<原因>；影响：<影响>。

## 风险与处理

| 风险 | 当前状态 | 处理方式或验证阶段 |
|---|---|---|
| ... | 待验证 | 阶段 01 ... |

## 当前阻断

- 无。

## 验证记录

| 日期 | 验证或证据 | 结果 |
|---|---|---|
| YYYY-MM-DD | 计划结构和链接检查 | 通过 |

## 实施偏差

- 暂无。实施方案变化时，在这里记录原计划、实际选择、原因和后续影响。

## 下一步

1. <下一项能够直接执行的任务>。
2. <完成后需要运行的验证>。
```

状态建议使用 `pending`、`in_progress`、`blocked`、`completed`。只有取得阶段门禁要求的证据后才能标记为 `completed`。

## 阶段划分检查

在定稿前确认：

- 阶段 01 能够消除关键未知事项，并建立后续阶段需要的验证能力。
- 数据迁移先于删除旧结构，兼容读取和回滚路径有明确期限。
- 高风险副作用在小范围可验证之后，才进入全量切换。
- 可观测性在需要依赖它判断发布是否成功之前完成。
- 最后阶段包含真实验收、分阶段发布、回滚演练和旧机制清理。
- 每个阶段都能形成有意义的独立提交，不需要一次修改所有模块才可验证。
